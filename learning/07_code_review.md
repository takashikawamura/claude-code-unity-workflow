# 07. コードレビュー・レビュー対応

## Step 6: コードレビュー

### レビュアー: GitHub Copilot

PR を作成後、GitHub Copilot に手動でレビューをアサインする。

**注意**: フリープランでは自動アサイン（GitHub rulesets/yml）が使えない。

### `.github/copilot-instructions.md`

このファイルを設定することで、プロジェクト固有のレビュー指示を与えられる：

```md
# コーディング規約
- ...
# Unity特有のルール
- ...
```

設定しない場合はデフォルト（バグ・セキュリティ・品質・可読性）のみチェックされる。

### AI レビューの運用方針

- **原則1回** とする
- 修正で大きな差分（新規ファイル追加・設計変更を伴う修正等）が発生した場合のみ再レビューを実施する
- 修正 → 再レビューのループは避ける（スタイル論への偏り・ノイズ増加を招く）

### Unity での注意

Unity 特性上、コードのみの変更では対応できないことが多い
→ レビュー対応は **Claude に一度戻す**のが良い

## Step 7: レビュー対応

### 流れ

1. **`/pr-review-to-plan`** でレビュー内容を基に対応プランを立てる
2. プランを確認・承認する（**脳死で OK するな**）
3. Claude が修正を実装する
4. **`/commit`** でコミット
5. **`/reply-review`** でレビューコメントに返信する

### レビューへの向き合い方

- レビューを1つ1つ精査する
- `AskUserQuestion` を使って「修正するか / スキップするか」を Claude に判断させる
- スキップする場合は理由を明記してコメント返信する

### Step 8: レビューコメントへのリプライ

```
/reply-review
```

Claude が各コメントへの返信を自動生成・投稿する。
