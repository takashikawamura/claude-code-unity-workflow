# 03. 仕様書作成・プラン作成

## Step 0: 仕様書の作成

### 流れ

1. 要件定義書を用意する、または要件を Claude に伝えて仕様書を作成してもらう
2. **必ず PlanMode でプランを作成してから** 仕様書を書く
3. `AskUserQuestion` で対話しながらプランを練り上げる

### 重要なルール

- 設計判断や方針は Claude に一方的に決めさせない → ユーザーに確認を取らせる
- 納得が行くまでプランを一緒に練る
- 要件定義書の機能要件は**実装に依存しない概念レベルの仕様**として記述する

### やってはいけないこと

- **脳死で OK するな** — 内容を理解せずに承認しない

---

## Step 1: プラン作成

### 流れ

1. 必ず **PlanMode** でプランを作成してから実装に入る
2. `AskUserQuestion` を使って対話しながらプランを練り上げる
3. **ユーザーがプランを承認するまで実装を始めさせない**

### プランに含めると良い内容

- 実装方針（一般的な方法 / Claude の推奨）
- 変更対象ファイルの一覧
- Issue の分割方針（大規模な場合）
- ブランチ名

### Tips: 実装方針の確認方法

```
「一般的な実装方法」と「Claude の推奨」の2つを聞いて、自分で方針を決める
```

これにより理解を深めながら設計判断ができる。

### 初めのプロンプト例

```
「○○を実装したい。一緒に考えましょう」
```

「一緒に考えましょう」とつけると安定する。AskUserQuestion で認識のすり合わせが行われる。
