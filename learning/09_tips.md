# 09. Tips・まとめ（TA 向け）

## TA 向け Tips

### ビジュアルの意図を言語化する

Claude はビジュアルを「見る」ことはできるが、「意図」は自分が伝える必要がある。
具体的なキーワードをつけるほど提案精度が上がる。

```
良い:
「有機的な形状が脈動するような、生命感のある発光エフェクト。
 色は緑〜青のグラデーション、周期は1.5秒」

悪い:
「生きてる感じのエフェクト」
```

---

### 参考画像を活用する

コンセプトアート・参考スクリーンショット・他ゲームのビジュアルを渡せる。

```
「この画像のような水面の反射表現を URP の Shader Graph で実装したい。
 一緒に考えましょう」
（画像をドラッグ&ドロップ）
```

---

### プランのセルフチェック

プランを作成してもらった後、別コンテキストで自己チェックをさせると精度が上がる。

```
「メインコンテキストのバイアスを引き継ぎたくないので
Subagent として、このプランの矛盾点・過不足を自己チェックしてお願い」
```

---

### ルール違反が起きたとき

なぜ命名規則やワークフローに従わなかったかを聞き、
再発防止策を Claude の **MEMORY に保存**させる。

```
「今回アセットをルール外のフォルダに配置しようとしたのはなぜ？
 再発防止のためにこの判断基準を MEMORY に保存して」
```

---

### 「なぜ」をつける

プロンプトに理由をつけると Claude の判断精度が上がる。

```
「URP で実装する理由: このプロジェクトはモバイル対応が必要なため
 Built-in RP は使えない。その前提でシェーダーを書いて」
```

---

## まとめ（4原則）

| 原則 | TA への応用 |
|---|---|
| **1. ルールは先に全部書く** | アセット命名規則・シェーダー規約を `.claude/rules/` に書いておく。毎回指示しなくても Claude が従う |
| **2. スキルで定型作業を封じ込める** | アセットの lint チェック・コミット手順をスキル化する |
| **3. Hooks で事故を防ぐ** | .meta ファイルの欠落・protected branch への直接 push を自動で止める |
| **4. 対話は設計判断に集中する** | ビジュアルの方向性・アルゴリズムの選択など、創造的な判断に時間を使う |

---

## 最重要メッセージ

> **書いてもらったコードは理解できるようにしっかりプランを練ろ！脳死で OK するな！**

TA にとっても同じ。
Claude が提案したシェーダーのアルゴリズムや VFX の構成は、
自分で理解した上で承認する。
理解できない部分は「説明して」と聞けば良い。
