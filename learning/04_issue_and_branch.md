# 04. Issue作成・ブランチ作成

## Step 2: Issue の作成

### スキル

```
/create-issue
```

### Issue に含める内容

| 項目 | 内容 |
|---|---|
| 概要 | 何をするか1〜2行で |
| 背景・目的 | なぜこの変更が必要か |
| 実現方法 | どうやって実装するか（箇条書き） |
| 完了条件 | チェックボックス形式で明確にする |

### Issue 分割の判断基準

- **変更ファイル数が多い** → Issue を分割する
- **影響範囲が広い** → Issue を分割する
- 1つの PR が適切な粒度に収まるようにする

### 大規模実装の場合

1. 基本設計書を作成する（実装手順を記載したもの）
2. 基本設計書から Issue を分割して作成する

### タスク管理ツール

Issue 以外でも OK：
- Linear
- `task.md` などのファイルベース管理

---

## Step 3: ブランチ作成

Claude が自動でブランチを作成する。

### ブランチ命名規則（参考）

```
feature/<issue番号>-<機能名>
refactor/<issue番号>-<機能名>
fix/<issue番号>-<バグ内容>
```

プランに含まれているブランチ名を確認して承認する。
