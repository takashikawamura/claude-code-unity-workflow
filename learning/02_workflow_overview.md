# 02. 開発ワークフロー全体像（TA 視点）

## 9ステップ概要

| ステップ | 内容 | スキル | 担当 | TA の関わり |
|---|---|---|---|---|
| 0 | 仕様書の作成 | — | 人間 + Claude | ビジュアル仕様を言語化する |
| 1 | プラン作成・承認 | — | 人間承認 / Claude | **必ず自分で読んで理解してから承認** |
| 2 | Issue 作成 | `/create-issue` | Claude | 制作タスクをチケット化 |
| 3 | ブランチ作成 | — | Claude | 自動（確認のみ） |
| 4 | **制作・検証** | `/lint-unity` | Claude + TA | **ここが TA の主作業** |
| 5 | コミット → Push → PR | `/commit-push-pr` | Claude + Hook | アセットのコミット |
| 6 | レビュー（原則1回） | — | GitHub Copilot | ビジュアル・命名規則の確認 |
| 7 | レビュー対応 | `/pr-review-to-plan` | 人間 + Claude | 指摘を精査して対応 |
| 8 | リプライ | `/reply-review` | Claude | 自動返信 |
| 9 | マージ | — | 人間（手動） | 最終確認してマージ |

## TA が特に注力するステップ

### Step 0-1: 仕様書・プランの作成

ビジュアルの意図を言語化する作業。
「どんな見た目？」「どんな動きをするエフェクト？」を具体的に書くほど Claude との連携が精度良くなる。

### Step 4: 制作（最重要）

詳しくは `05_ta_workflow.md` と `06_vfx_shader.md` を参照。

### Step 5: コミット

アセットファイル（.shadergraph, .vfx, .mat など）のコミット。
バイナリ扱いに注意（→ `07_commit_review.md`）。

## 人間が必ず関与するポイント

1. **プランの承認**（Step 1）— 内容を理解せずに OK しない
2. **`/pr-review-to-plan` の実行**（Step 7）— レビューを精査する
3. **マージ**（Step 9）— 最終ビジュアル確認後にマージ
