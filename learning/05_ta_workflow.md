# 05. TA としての制作フロー（Step 4）

ここが TA にとって最も重要なステップ。

---

## Claude への指示の仕方（ビジュアル編）

### 基本：「見た目」を言語で伝える

```
悪い例:
「かっこいいエフェクトを作って」

良い例:
「水面に落ちた石の波紋エフェクトを VFX Graph で作りたい。
 波紋は3重の同心円で広がり、2秒でフェードアウトする。
 マテリアルはアルファクリッピングを使ったリングシェーダーを想定している。
 一緒に考えましょう」
```

### 参考画像を渡す

Claude Code は画像ファイルを読める（スクリーンショット・コンセプトアート）。

```
「この画像のようなグロウ表現を Shader Graph で実装したい」
（画像をドラッグ&ドロップ）
```

---

## UnityMCP を使ったシーン確認

UnityMCP があると Claude が Unity Editor の状態を確認できる。

### できること

- シーン内のオブジェクト一覧を確認する
- 選択中オブジェクトのマテリアル・コンポーネントを確認する
- VFX Graph の再生状態を確認する
- パーティクル数・GPU 使用状況を確認する

### 活用例

```
「今シーンにある FirePillar オブジェクトのマテリアルのプロパティを確認して、
 Color パラメーターの値を一覧で教えて」
```

## アセット制作の流れ

### VFX Graph の場合

1. Claude と一緒にノード構成のプランを立てる
2. VFX Graph エディターで手動でノードを配置する
3. Custom HLSL が必要な場合は Claude に書いてもらう
4. 調整しながら Claude に `.vfx` ファイルを読ませてレビューしてもらう

### Shader Graph の場合

1. Claude と一緒にシェーダーのアルゴリズムを設計する
2. Shader Graph エディターで手動でノードを配置する
3. Custom Function ノードの HLSL コードは Claude に書いてもらう
4. `.shadergraph` ファイルを Claude に読ませて確認してもらう

### マテリアル・アセット整理の場合

1. Claude に `.mat` ファイルや フォルダ構成を確認させる
2. 命名規則違反・プロパティの不整合を検出させる
3. 一括リネームや整理の手順を提案させる

## lint（Unity 特有ルールのチェック）

スキル: `/lint-unity`

TA にとって有効なチェック内容：

- アセットの命名規則違反
- フォルダ構成のルール違反
- マテリアルの未設定プロパティ
- VFX Graph の未接続ノード
- Shader Graph のコンパイルエラー

---

## パフォーマンス確認

Claude + UnityMCP でパフォーマンス情報を確認しながら調整できる。

```
「現在の FirePillar VFX のパーティクル数と GPU コストを確認して、
 モバイル向けに削減できる箇所を提案して」
```
