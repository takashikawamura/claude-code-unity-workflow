# 11. Tips・まとめ

## Tips

### プランの自己チェック

プランを作成してもらった後、**矛盾点や過不足がないか自己チェックをしてもらうと精度が上がる**。

```
「メインコンテキストのバイアスを引き継ぎたくないので
Subagent として自己チェックをお願い」
```

同じコンテキストでやるとバイアスがかかる → 別コンテキストでやると厳重なチェックになる。

---

### CLAUDE.md / rules/ の言語

| 言語 | メリット |
|---|---|
| 英語 | トークン消費を抑えられる |
| 日本語 | 人間も読んで修正できる |

→ 人間が修正する必要があるため、日本語でも OK。

---

### ルール違反が起きたとき

なぜワークフローに従わなかったかを聞き、**再発防止策を Claude の MEMORY に保存させる**。

- MEMORY はローカル機能なので開発者間の共有はできない
- MEMORY 機能は ClaudeCode v2.1.32（2025/2/5 リリース）から利用可能

---

### UI の実装

**uGUI よりも UI Toolkit で UI を作ると Claude との相性が良い**。

- UXML / USS はテキストファイルなので Claude が直接読み書きできる
- MCP でシーンを操作するより効率的

---

### プロンプトのコツ

- **「なぜの理由」をつける** → 意図を把握してくれる
- 「一緒に考えましょう」をつけると安定する

---

### 全自動化について

全自動化はできるが、**案件ではコード把握のため全自動化は非推奨**。

---

## まとめ（4原則）

| 原則 | 内容 |
|---|---|
| **1. ルールは先に全部書く** | CLAUDE.md + rules/ にルールを書いておけば毎回指示しなくても Claude が従う。初期投資で以降の対話コストが大幅に下がる |
| **2. スキルで定型作業を封じ込める** | テスト・lint など手順が決まっている作業はスキル化する。品質が安定する |
| **3. Hooks で事故を防ぐ** | 人間も Claude も間違える。致命的な操作（protected branch への push 等）は自動で止める |
| **4. 対話は設計判断に集中する** | 定型作業をスキル・Hooks に委譲した分、PlanMode での設計議論に時間を使える |

---

## 最重要メッセージ

> **書いてもらったコードは理解できるようにしっかりプランを練ろ！脳死で OK するな！**
